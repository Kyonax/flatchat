The avatar converter (`tools/converter/src/avatar/`, MPL-2.0) turns an upload (VRM 0.x, VRM 1.0, a plain GLB) into the platform's own format: four VRM 1.0 GLB levels, a thumbnail and a manifest (`packages/content/src/avatar.ts`, Apache-2.0, shared with the core and the client), each named by its SHA-256. The client draws only these (R-18). FBX, OBJ, DAE and `.blend` uploads reach it as GLB (rule `model-formats`, S5.08). Creators' guide: `docs/avatars.md`.

## The Files

| File | Job |
|---|---|
| `convert.ts` | `convertAvatar(bytes, {ktx2})` (converter 1.3.0): size, `readGltf`, Khronos glTF-Validator plus vrm-validator for VRMs (errors refuse but for `REPAIRED`), `rules` (data inside the GLB, `extensionsRequired` within `REQUIRED_OK`, `AVATAR_LIMITS`), migrate or map, required bones, turn round, clean-up (skeleton hints, animations, cameras, lights, `dedup`, `prune` with `keepLeaves`), one clean GLB, then each level built from it with its texture limits, the stats and `rankOf`, the manifest |
| `vrm.ts` | `VRMExtension` / `VRMData`: VRMC_vrm, VRMC_springBone, per-material MToon (and HDR emissive), per-node constraints read into one property; every index becomes a slot (`{$node}`, `{$material}`, `{$image}`, `{$texture,…}`) held in a `RefMap` keyed by slot number, so disposing a node never renumbers the others; `write` puts the written file's indices back and `dropEmpty` leaves out the empty lists VRM 1.0's schema forbids |
| `vrm0.ts` | `migrateVrm0(json)`: VRM 0.x to 1.0 at the JSON level, by three-vrm's own import rules (preset renames, thumb renames, morph binds from meshes to nodes, weights /100, material values to colour and texture-transform binds, first-person annotations to nodes, look-at range maps and the -z offset, spring groups to chains with the 7 cm leaf tail as a new node, colliders with -z, empty collider groups left out and renumbered, MToon and unlit shaders ported from three-vrm-materials-v0compat, MIT) |
| `humanoid.ts` | `HUMAN_BONES` with parents, `REQUIRED_BONES`, `IMPOSTOR_BONES` (20); `humanBoneOf`/`mapByNames` for plain rigs (prefix and side stripping; spine links mapped by depth below the hips, since rigs number them); `facesPlusZ`, `turnAround` (conjugate every transform, IBM, vertex and morph delta with a half turn about Y), `turnVrmAround` |
| `lod.ts` | `makeLod1` (half, expression-moved vertices locked), `makeLod2` (a fifth, only mouth and blink targets and expressions kept and renumbered), `mergeMaterials` (one atlas per alpha mode and sidedness, UVs through KHR_texture_transform then folded into the slot, the largest material's MToon with the atlas as colour and shade), `joinWithTargets`, `makeImpostor` (world-space rest positions, weights to the nearest kept ancestor bone, 512 px atlas, about 1,500 triangles, only the kept bones' tree left): simplified with `simplifyWithAttributes`, each vertex's place in two strides as attributes (`STRIDE_WEIGHT` 2 over the mesh's size), then, while over 2,000, `sloppyByBone` grid-merges each bone's part on its own vertices, keeping triangles between bones as they are |
| `stride.ts` | `STRIDES` (thighs ±0.6 rad, knees 0.5 and 0.9), `strideMatrices` (each bone's posed world × rest world⁻¹, the turn about world X at the joint written in its frame), `posePositions`, `stretchedTriangles` (longest edge over twice and 10 cm over its rest length), `impostorStretch(doc, humanoid)` for tests and `scripts/impostor-audit.ts`; `matrix.ts` the column-major 4×4 helpers |
| `samples.ts` | `sampleAvatar('vrm1' / 'vrm0' / 'glb' / 'free')` (the free one a robot of four rigid boxes): one 1.75 m humanoid with fingers, a spring hair chain, mouth and blink shapes and a checker, written as each tool would (VRM 0.x facing -Z with materialProperties; the GLB with Mixamo names) |
| `../avatar-cli.ts` | The core's per-upload program: UPLOAD OUTDIR, files by hash, `manifest.json`, then `result.json` (`{ok,id,manifest}` or `{ok:false,problems}`); exit 0, 1, 2 |
| `../item-cli.ts` | The same for items (S5.05): UPLOAD OUTDIR KITS, the three bodies read from KITS (`kits/bodies/`, each VRM checked against `kits.json`'s SHA-256, then `kitBody`), one file per fit or the prop, the manifest, `result.json`; the core allows it reads of KITS too |
| `../sandbox.ts` | `--import` hook (`module.registerHooks`, in-thread): `sharp` (pulled in by glTF-Transform's functions through ndarray-pixels) resolves to a stub, so the sandbox keeps native addons off |
| `../textures.ts` | `decodeImage`, `halve`, `gpuBytes`, `fitTextures(docs, {side, budget}, ktx2, warn)`: shared with the world converter |

## The Rules

| Rule | Why |
|---|---|
| The client parses only the converter's levels, checked by `packages/content` (`checkManifest`) first; the upload as it came never leaves the core | R-18, T-03: one parser path, ours |
| Repair, do not refuse, the four validator errors in `REPAIRED`; refuse every other error | 68 real avatars (VRoid's UniVRM 0.x, Blender's exporter) showed exactly these four; refusing them refuses VRoid Studio itself |
| Never index VRM references by list position; use `VRMData`'s slots (`data.node(slot)`, `addNode`) | A disposed node (the impostor drops 30-odd) renumbered a list and the impostor lost its humanoid |
| A VRM 0.x goes through `migrateVrm0` then `turnAround` and `turnVrmAround`: the JSON migration writes VRM 0.x's frame (three-vrm's -z fixes), the turn then flips x and z of every local and world vector | VRM 1.0 faces +Z with the left hand at +X; bones that had no rotation keep none |
| Morph target names live on `PrimitiveTarget` names: glTF-Transform writes `extras.targetNames` from them | Set on the mesh's extras alone, they were written as empty strings |
| `joinPrimitives` drops morph targets: join a mesh's primitives with `joinWithTargets` | LOD1 lost its face before |
| Lighter levels merge materials (`mergeMaterials`); LOD0 keeps the authored ones for the nearest few | S0.09: VRoid's 15 to 17 materials, 1,848 draw calls for the crowd; merged, 85. A VRoid avatar's LOD1 goes from 65 slots to 8 |
| The core runs `avatar-cli.ts` with `--permission`, `--allow-fs-read` of the code and the upload only, `--allow-fs-write` of its folder only, `--import sandbox.ts`, a time and memory limit, and a network namespace where `unshare` allows one | Node.js 24's permission model limits files, addons, workers and child processes but not the network |
| A model the humanoid does not fit is a free shape (S4.11), never refused for it: `completeFreeShape` (humanoid.ts) makes a hips node at the model's middle holding the whole scene when there is none, and every missing required bone as an empty node where a body would have it (`STAND_INS`, shares of the height); `manifest.shape` is `free` and a warning names the bones made. Only a model with no mesh at all is refused | three-vrm refuses a humanoid without its required bones; empty ones cost nothing and let the shared motions move what the model has |
| Never grid-merge (`simplifySloppy`) a skinned mesh as a whole, and give a grid merge only the vertices of the part it merges | It joins what a walk pulls apart: before converter 1.2.0, 8 of 68 real avatars' impostors (the VRoid and Blender ones, whose hair cards and seams stall the careful simplifier) walked with a sheet between the legs or a sliver from the feet, 4 to 111 stretched triangles each; and a grid given the whole vertex buffer picked a right foot's vertex for a left foot's cell. After: none, at 1,409 to 1,528 triangles (`scripts/impostor-audit.ts`) |
| Keep only the extensions the client draws (`dropForeignExtensions`, also used on the body kits): `LEVEL_EXTENSIONS` from packages/content, a warning per extension left out, an emissive strength folded into the emissive colour first; and check every level made with the client's own `checkAvatarLevel` (a level it would refuse fails the conversion) | Before converter 1.3.0 a Blender export's KHR_materials_clearcoat went through and the client refused every level, so the avatar was "ready" and never drawn; Blender's white emission at strength 0 turned white once its strength was dropped |
| Changing what the converter makes: bump `AVATAR_CONVERTER_VERSION`, rewrite `test/golden/avatars.json` with `FLATCHAT_GOLDEN_WRITE=1` and read its diff | The golden file pins kinds, ranks, each level's triangles, bones and slots, expressions, heights and warnings |
